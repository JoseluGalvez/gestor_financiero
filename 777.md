## Plan de Desarrollo

### 1. Cache de datos - IndexedDB con TTL
**Objetivo**: Reemplazar localStorage por IndexedDB para datos SEC con TTL

**Implementación propuesta**:
```typescript
const EDGAR_CACHE_KEY_PREFIX = 'edgar_cache_v1_';
const CACHE_TTL_MS = 30 * 24 * 60 * 60 * 1000; // 30 días

const db = await openDB('edgar-cache', 1, {
  upgrade(db) {
    db.createObjectStore('facts', { keyPath: 'cik' });
  }
});

async function getFromCache(cik: number): Promise<EdgarCompanyFacts | null> {
  const entry = await db.get('facts', cik);
  if (!entry) return null;
  if (Date.now() - entry.timestamp > CACHE_TTL_MS) {
    await db.delete('facts', cik);
    return null;
  }
  return entry.data;
}
```

## Registro de cambios — Integración de APIs de apilayer

**Fecha**: 2026-09-09

### Contexto
Se investigaron los 69 repositorios de la organización **apilayer** en GitHub buscando APIs de finanzas útiles. De entre todas, se identificaron dos repositorios activos con potencial real de integración:

- **[global-rates](https://github.com/apilayer/global-rates)** — Dashboard de divisas que usa la API *Exchange Rates Data API* para obtener tasas de cambio最新imas, históricas y de fluctuación.
- **[stockometer](https://github.com/apilayer/stockometer)** — Tracker de acciones que usa la API *Marketstack* para datos intradía, EOD e info de tickeres.

Ambas APIs requieren una API key gratuita (con cuota limitada en el plan free) y se consumen vía HTTP JSON.

---

### Cambios realizados

#### 1. `marketstack-adapter.ts` (nuevo)
**Por qué**: El proyecto actual obtiene datos de acciones solo vía Yahoo Finance (proxy local, no apto para producción) y Stooq (solo datos diarios CSV, con protección anti-bot). Marketstack ofrece datos **intradía y EOD** de más de 170,000 tickeres en formatos JSON estructurados, con soporte para consulta por rango de fechas y límite de registros. Esto cierra la brecha de datos intradía que faltaba.

**Qué hace**:
- `normalizeEodCandles()` — Normaliza respuestas EOD a tipo `OHLCV` (reutiliza el tipo existente de `financial-technical.ts`)
- `normalizeIntradayCandles()` — Normaliza respuestas intradía, extrayendo solo la parte de fecha
- `normalizeTickerQuote()` — Normaliza la info de un ticker (precio, cambio, volumen, exchange)
- `fetchMarketstackEod()` — Fetch de velas diarias con autenticación
- `fetchMarketstackIntraday()` — Fetch de velas intradía
- `fetchMarketstackTicker()` — Fetch de quote en tiempo real de un ticker

**Dependencia**: Requiere variable de entorno `MARKETSTACK_API_KEY`.

---

#### 2. `marketstack-adapter.test.ts` (nuevo)
**Por qué**: Cada adaptador de datos del proyecto tiene cobertura de pruebas independiente (ver `ecb-fx-adapter.test.ts`, `stooq-ohlc-adapter.test.ts`, `market-adapters.test.ts`). Este archivo asegura que la normalización y el manejo de errores de Marketstack funcionen correctamente antes de integrarse en producción.

**Qué cubre**: 12 pruebas — normalización de EOD, normalización de intradía, normalización de ticker, fetch con mock (éxito, error HTTP, error de API, API key faltante).

---

#### 3. `exchangerates-adapter.ts` (nuevo)
**Por qué**: El adaptador FX actual (`ecb-fx-adapter.ts`) usa Frankfurter (datos ECB gratuitos, sin key). Sin embargo, el repositorio `global-rates` demuestra que la API *Exchange Rates Data API* ofrece funcionalidades adicionales que Frankfurter no tiene: **fluctuación entre fechas** (para ver variación de pares FX en un rango) y **series temporales** (histórico completo). Esto complementa el adaptador existente sin reemplazarlo.

**Qué hace**:
- `normalizeLatestResponse()` — Normaliza tasas最新imas
- `normalizeFluctuationResponse()` — Normaliza datos de fluctuación (start_rate, end_rate, change, change_pct)
- `normalizeTimeseriesResponse()` — Normaliza series históricas por fecha
- `fetchLatestRates()` — Fetch de tasas最新imas
- `fetchFluctuation()` — Fetch de variación entre dos fechas
- `fetchTimeseries()` — Fetch de serie temporal histórica

**Dependencia**: Requiere variable de entorno `EXCHANGERATES_API_KEY`.

---

#### 4. `exchangerates-adapter.test.ts` (nuevo)
**Por qué**: Misma lógica que el punto 2. Asegura que la normalización de las tres respuestas (latest, fluctuation, timeseries) y el manejo de errores estén cubiertos.

**Qué cubre**: 14 pruebas — normalización de latest, fluctuation y timeseries, fetch con mock (éxito, error HTTP, API key faltante), filtrado de monedas inválidas.

---

#### 5. `market-adapters.ts` (modificado)
**Por qué**: El registro central de fuentes de datos (`ADAPTER_REGISTRY`) y el sistema de estados (`buildAdapterStatuses`) necesitan conocer Marketstack como fuente válida. Sin este cambio, el panel de "Fuentes de datos" de la aplicación no mostraría Marketstack y no se podría activar/desactivar.

**Cambios específicos**:
- Añadido `'marketstack'` al tipo `DataSourceId` (línea 3) — para que TypeScript reconozca la nueva fuente
- Añadida entrada en `ADAPTER_REGISTRY` con `id: 'marketstack'` — describe la fuente, su procedencia y alcance de licencia
- Ampliado `buildAdapterStatuses()` para aceptar un cuarto parámetro `marketstack?` — controla si la fuente está activa (`ok`), con error (`error`) o sin configurar (`degraded`)
- Añadida prueba en `market-adapters.test.ts` que verifica que `marketstack` aparece como `degraded` por defecto y como `ok` cuando se provee

---

#### 6. `market-adapters.test.ts` (modificado)
**Por qué**: La prueba existente de `buildAdapterStatuses` solo verificaba coingecko, ecb y yahoo. Al añadir el parámetro `marketstack`, la firma de la función cambió y la prueba existente necesitaba actualizarse, además de añadir una prueba específica para el nuevo comportamiento.

**Cambios**: Se añadió una segunda prueba `it('marca marketstack ok cuando se provee')` que valida que al pasar el cuarto argumento, Marketstack se marca como `ok` con la latencia correcta.

## Registro de cambios — Sprint 1 Completado (IndexedDB Cache + Tests)

**Fecha**: 2026-09-15

### Contexto
El roadmap definía Sprint 1 (2 semanas) con tres objetivos: IndexedDB cache con TTL, validación Zod y tests unitarios de cache. La validación Zod ya existía en `src/validation.ts`. La implementación de IndexedDB en `sec-edgar-adapter.ts` tenía un bug en la expiración TTL y carecía de tests.

---

### Cambios realizados

#### 1. `sec-edgar-adapter.ts` (modificado) — Fix de bug crítico en TTL
**Por qué**: La función `getFromCacheIndexedDb` eliminaba entradas expiradas pero **seguía devolviendo los datos stale** (línea 380-384). Esto rompía la semántica de TTL: el consumidor recibía datos caducados sin saberlo.

**Qué hace**:
- Fix: `return resolve(null)` tras borrar entrada expirada (línea 383)
- Añadido parámetro opcional `now: number = Date.now()` a 4 funciones para tests deterministas:
  - `putInCacheIndexedDb(cik, data, now?)`
  - `getFromCacheIndexedDb(cik, now?)`
  - `cacheTickers(entries, now?)`
  - `getCachedTickers(now?)`
- Exportada `resetIndexedDbCache()` para aislar tests (limpia singleton `indexedDb`)

---

#### 2. `sec-edgar-adapter.test.ts` (modificado) — 9 tests nuevos de IndexedDB
**Por qué**: La implementación de IndexedDB existía desde antes pero **sin cobertura de tests**. El módulo usaba un singleton global (`indexedDb`) que impedía aislar tests entre sí.

**Qué cubre** (9 tests):
| Test | Qué verifica |
|------|--------------|
| `putInCacheIndexedDb stores facts with timestamp` | Guarda CIK, data y timestamp exacto |
| `getFromCacheIndexedDb returns cached facts within TTL` | Devuelve data si no expiró |
| `getFromCacheIndexedDb returns null for expired cache` | **Fix validado**: devuelve `null` y borra entrada tras 30+ días |
| `getFromCacheIndexedDb returns null for missing key` | Clave inexistente → `null` |
| `clearCacheIndexedDb clears all facts` | Limpia store `facts` completo |
| `cacheTickers stores ticker directory` | Guarda directorio con key fija y timestamp |
| `getCachedTickers returns entries within TTL` | Directorio válido dentro de 24h |
| `getCachedTickers returns null for expired ticker cache` | Expirado >24h → `null` |
| `getCachedTickers returns null when no cache exists` | Sin cache previa → `null` |

**Técnica**: Mock completo de `indexedDB` global con `queueMicrotask` para simular callbacks asíncronos de IDB. Uso de `vi.hoisted` para mockear `Date.now()` de forma determinista sin `vi.useFakeTimers()` (evita colisiones con vitest).

---

#### 3. `src/validation.ts` (existente) — Ya implementado
**Estado**: ✅ Completo antes de este sprint. Contiene schemas Zod para:
- `companyFundamentalsSchema` — 29 campos con validaciones de rango, opcionales, nulos

- `formFieldSchema` — Validación genérica de campos de formulario
