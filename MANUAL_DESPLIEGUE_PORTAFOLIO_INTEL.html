01 · Antes de empezar

Propósito, alcance y estado del producto

Portafolio Intel es una aplicación Next.js para consolidar información de cartera en una base de datos Supabase con acceso por organización, visualización Recharts, alertas, informes y análisis explicable.

Alcance funcional actual. La aplicación está deliberadamente vacía tras la instalación: no fabrica cifras financieras. El dashboard se alimenta de snapshots, cotizaciones, alertas y análisis persistidos. La previsualización de Google Sheets existe; la importación OAuth de una hoja real es una siguiente fase de backend.
ÁreaEstado actualQué puede hacer el operador
Acceso y organizaciónImplementadoAcceder por enlace seguro y crear la primera organización/cartera.
Dashboard y RealtimeImplementadoConsultar KPIs y gráficas cuando se escriban datos en Supabase.
FuentesConfiguraciónRegistrar Google Sheets, CSV, XLSX o SQL y previsualizar el ejemplo sin escribir filas.
Importación Google realPendienteRequiere OAuth de servidor, confirmación de lote y conciliación.
Fiscalidad y recomendacionesRevisión obligatoriaUsar únicamente borradores y cálculos de apoyo; nunca presentar ni ejecutar decisiones automáticamente.

El repositorio que acompaña a este manual es github.com/JoseluGalvez/gestor_financiero. Mantenga la rama main como referencia de producción y trabaje en ramas para cambios.

02 · Ruta rápida

Primer arranque en diez minutos

Esta ruta deja el servidor local listo, pero no crea por sí misma un proyecto Supabase ni introduce datos financieros.

1

Clonar

Obtenga una copia local del repositorio y acceda al directorio del proyecto.

2

Instalar

Use npm ci para reproducir exactamente el lockfile del repositorio.

3

Configurar

Cree .env.local con la URL y clave publicable del proyecto Supabase.

4

Validar

Ejecute pruebas, lint y build antes de trabajar con datos reales.

5

Arrancar

Inicie el servidor y abra http://localhost:3000.

6

Crear espacio

Entre por enlace seguro y cree organización y cartera inicial.

git clone https://github.com/JoseluGalvez/gestor_financiero.git
cd gestor_financiero
npm ci
cp .env.example .env.local
npm run test:unit && npm run lint && npm run build
npm run dev
Resultado esperado. Next.js mostrará la dirección local. Abra el navegador, solicite un enlace de acceso y complete el alta de la organización. Un dashboard vacío en este punto es correcto.
03 · Preparación

Requisitos y cuentas necesarias

Next.js 16.3.1 declara Node.js 20.9.0 o superior. Para un ciclo de trabajo fluido, prepare Git, una cuenta GitHub, una cuenta Supabase y un navegador moderno. Para producción se recomienda conectar GitHub a Vercel o a un proveedor equivalente compatible con Next.js.

ElementoMínimoComprobación
Node.js20.9.0+node --version
npmIncluido con Node.jsnpm --version
GitVersión recientegit --version
SupabaseProyecto activoURL de proyecto y clave publicable
VercelOpcional en local; recomendado en producciónCuenta vinculada a GitHub
Regla de seguridad. La clave publicable puede vivir en el frontend cuando RLS está activo. Las claves secretas, service_role, contraseñas SQL y tokens OAuth no pertenecen al repositorio, a .env.local versionado ni a variables NEXT_PUBLIC_*.
04 · Entorno local

Descargar, instalar y ejecutar

1

Clone el repositorio

GitHub mantiene una copia local del historial y los archivos con git clone. Si el repositorio fuera privado, autentíquese por HTTPS o SSH antes de clonar.[1]

git clone https://github.com/JoseluGalvez/gestor_financiero.git
cd gestor_financiero
git status
2

Instale dependencias bloqueadas

Utilice npm ci, no npm install, para una instalación reproducible desde package-lock.json. El comando falla si el lockfile no coincide y no lo reescribe.[2]

npm ci
3

Prepare el entorno local

Copie la plantilla. Edite solo los dos valores publicables; no cambie el nombre de las variables.

cp .env.example .env.local
# Abra .env.local y sustituya los marcadores:
NEXT_PUBLIC_SUPABASE_URL=https://<proyecto>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_<clave-publicable>
4

Compruebe la calidad y arranque

npm run test:unit
npm run lint
npm run build
npm audit --omit=dev --audit-level=high
npm run dev

Abra http://localhost:3000. Para simular una ejecución de producción local utilice npm run build && npm start.

05 · Datos y seguridad

Configurar Supabase y las políticas RLS

Supabase actúa como fuente de verdad. La aplicación cliente se autentica con una clave publicable; cada operación sobre una fila se filtra con Row Level Security por pertenencia a organización.

Crear o reutilizar el proyecto

  1. En Supabase, cree o seleccione un proyecto en la región apropiada para los usuarios y obligaciones de datos.
  2. Copie la URL del proyecto y una Publishable key activa a .env.local.
  3. Conserve las migraciones del directorio supabase/ como registro de esquema. Para un proyecto nuevo, adapte el identificador del proyecto y aplíquelas de forma controlada mediante migraciones, no pegando credenciales ni usando producción para pruebas.
  4. Despliegue la Edge Function bootstrap-organization y configure sus secretos en el panel de Supabase.

Variables y secretos

UbicaciónValoresPropósito
Frontend / VercelNEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY		Conectar el cliente web autenticado.
Edge FunctionAPP_ORIGINRestringir CORS al dominio exacto de la aplicación.
Edge Function / futuro importadorClave secreta, OAuth Google, cifradoSolo backend; jamás se expone al navegador.

Qué protege RLS

Las políticas activas permiten a un miembro leer únicamente las filas de su organización; propietarios y editores pueden modificar solo los recursos autorizados. La propia plataforma recomienda activar RLS en cada tabla expuesta, reducir grants y probar permisos permitidos y denegados.[3]

Usuario autenticado
→

→
Política RLS
→

No omita este paso. Una clave secreta o service_role omite RLS. Úsela exclusivamente en funciones de servidor y rote la clave si se sospecha una exposición.
06 · Primera sesión

Crear organización y recorrer el dashboard

1

Solicite un enlace de acceso

Introduzca su correo en la pantalla de acceso. El cliente solicita un enlace de un solo uso a Supabase Auth y vuelve al mismo origen configurado.

2

Nombre la organización

Tras autenticarse, indique el nombre de la organización. La función segura crea el perfil, organización, membresía owner, cartera principal y un evento de auditoría.

3

Comprenda el estado vacío

Sin transacciones conciliadas ni snapshots, la interfaz no mostrará valor de cartera ni tendencias. Esto protege contra cifras de ejemplo que pudieran confundirse con datos reales.

4

Interprete las secciones

SecciónUso operativo
ResumenKPIs, evolución y alertas abiertas de la organización.
CarteraPosiciones persistidas, asignación y acceso al detalle de activos.
AnálisisMétricas y ejecuciones explicables; se bloquean si la cobertura es insuficiente.
FuentesRegistro de orígenes de datos y configuración de mapeos.
Fiscalidad / InformesResumen PDF y borradores que requieren revisión; no presenta declaraciones.
07 · Ingesta controlada

Fuentes, previsualización e importación

La aplicación no explora automáticamente hojas ni bases de datos. El operador indica qué fuente, pestaña, rango y columnas autoriza. Este modelo reduce el riesgo de leer datos no seleccionados.

Probar el flujo sin datos financieros reales

  1. Abra Fuentes y elija Usar hoja ficticia.
  2. Compruebe que se rellenan URL/ID, pestaña Transacciones ficticias, rango A1:I7 y el mapeo de Fecha, Instrumento, Tipo, Cantidad, Precio y Divisa.
  3. Seleccione Previsualizar sin importar. El sistema muestra filas aceptadas/rechazadas y mantiene el estado de solo lectura.
  4. Registre la fuente solo si su configuración es correcta. El registro queda pending; no crea movimientos financieros.

Qué falta para una hoja real

La sincronización real exige un cliente OAuth de Google de mínimo privilegio, alcance de lectura, autorización del usuario, cifrado de refresh tokens, un proceso de servidor que valide filas, deduplicación por external_id, creación de sync_runs y confirmación antes de escribir. Google recomienda solicitar permisos de forma incremental y conservar tokens de refresco en almacenamiento seguro.[4]

Importación responsable. Utilice una hoja de pruebas separada y datos sintéticos para validar conectividad. No conceda acceso global a Drive ni pegue tokens, JSON de cuentas de servicio o contraseñas SQL en el formulario.
08 · Entrega

Despliegue rápido en producción con Vercel

Vercel es la ruta recomendada para este proyecto Next.js porque despliega desde Git y puede crear previews para ramas y despliegues de producción al integrar cambios en la rama principal.[5]

1

Importe el repositorio

Inicie sesión en Vercel con GitHub, seleccione JoseluGalvez/gestor_financiero, detecte Next.js y mantenga el directorio raíz por defecto.

2

Defina la compilación

Install Command: npm ci
Build Command:   npm run build
Output:          valor detectado por Next.js

No configure una exportación estática: la aplicación depende de autenticación y de acceso a Supabase en tiempo de ejecución.

3

Configure variables por entorno

En Vercel → Project Settings → Environment Variables, cree las dos variables NEXT_PUBLIC_* para Production y, de forma separada, para Preview/Staging si utiliza otro proyecto Supabase. Nunca copie secretos de Edge Function a Vercel solo para que lleguen al navegador.

4

Configure el origen de la función

En Supabase → Edge Function Secrets, establezca APP_ORIGIN con el dominio HTTPS de producción, por ejemplo https://app.ejemplo.com. Configure en Supabase los secretos del futuro importador, no en el bundle frontend.

5

Despliegue y compruebe

Pulse Deploy. Después solicite un magic link, cree una organización de prueba, compruebe que no se ven filas de otra organización y ejecute los controles de salida descritos en la sección 9.

09 · Operación sostenible

Pruebas, seguridad y mantenimiento

Puerta de calidad antes de cada despliegue

npm ci
npm run test:unit
npm run lint
npm run build
npm audit --omit=dev --audit-level=high

Las pruebas unitarias actuales verifican el mapeo de la previsualización ficticia: aceptan las seis columnas obligatorias y rechazan un encabezado ausente. Cuando exista el importador real, añada pruebas de integración contra un proyecto Supabase y hoja de Google independientes de producción.

Checklist de producción

  • Las variables NEXT_PUBLIC_* apuntan al proyecto de entorno correcto.
  • APP_ORIGIN está definido con HTTPS y el dominio exacto de producción.
  • RLS está activa en tablas y vistas expuestas; se prueban accesos permitidos y denegados.
  • No hay tokens OAuth, claves secretas ni .env.local en Git.
  • La auditoría de npm no contiene vulnerabilidades altas o críticas sin una excepción aprobada.
  • Los informes fiscales continúan identificados como borradores de revisión.
  • Hay una copia de seguridad y una persona responsable de rotar secretos e investigar alertas.

Mejoras de seguridad planificadas

Antes de abrir el acceso a más usuarios, priorice límite de tasa e idempotencia en el aprovisionamiento de organizaciones, cabeceras CSP/anti-clickjacking en Next.js, APP_ORIGIN obligatorio en producción y políticas RLS separadas por operación. Consulte PRUEBAS_Y_SEGURIDAD_PRODUCCION.md para el detalle técnico.

11 · Lenguaje común

Glosario

API key publicableIdentificador de una aplicación web. Puede aparecer en el cliente, pero debe combinarse con autenticación y RLS.
Edge FunctionFunción de backend desplegada cerca de la base de datos. Es el lugar adecuado para secretos y operaciones privilegiadas.
External IDIdentificador de origen usado para detectar importaciones duplicadas de una misma transacción.
Magic linkEnlace de un solo uso enviado por correo para iniciar sesión sin contraseña.
Portfolio snapshotFotografía de valor, coste y rendimiento de una cartera en un momento determinado; alimenta las gráficas.
Preview / previsualizaciónLectura y validación de filas que no modifica la base de datos.
RLSRow Level Security: reglas PostgreSQL que determinan qué filas puede leer o modificar cada identidad.
RealtimeCanal que comunica cambios persistidos al dashboard sin recargar la página. No equivale por sí solo a una cotización externa en vivo.
Refresh tokenCredencial de larga duración que permite renovar un acceso OAuth. Debe cifrarse y mantenerse solo en backend.
Service roleClave administrativa que evita RLS. Nunca debe viajar al navegador ni aparecer en el repositorio.
Sync runRegistro de una ejecución de ingesta con origen, resultado, conteos y error seguro.
Vercel PreviewDespliegue temporal asociado a una rama o pull request antes de fusionarlo a producción.
