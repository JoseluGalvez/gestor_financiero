Políticas RLS y Permisos

JWT Original del Usuario

Se utiliza exclusivamente el token de sesión del usuario para consultar Supabase. Las políticas RLS bloquean el acceso a organizaciones o carteras ajenas.

Restricción de Clave de Servicio

La clave de servicio (Service Role) se reserva para adaptadores y auditoría. Nunca se emplea para leer carteras privadas.

Consentimiento Explícito

El agente verifica en backend que el usuario haya aprobado el uso de su cartera antes de adjuntar cualquier contexto privado.

Ejemplo de Política RLS (PostgreSQL)
-- Lectura: consulta propia u owner
CREATE POLICY agent_query_runs_read ON public.agent_query_runs
FOR SELECT TO authenticated
USING (actor_id = auth.uid() OR public.is_organization_owner(organization_id));

-- Evitar inserciones directas desde cliente
CREATE POLICY client_insert_reject ON public.agent_query_runs FOR INSERT TO authenticated WITH CHECK (false);
